WHY A SECOND MEASUREMENT WAS NEEDED
M7 closed with one boot sample retained in `m7-after-room-stats.json`: 1,557 ms, with its own caveat —
"Boot time is one sample, so it is not comparable as a trend." M8's first single sample read 2,183 ms,
which would have been reported as a 40% regression on the strength of one number each. Six samples per
milestone, taken back to back on an idle machine, were measured instead:

BOOT TO FIRST RENDERED FRAME (time until the room instance exists; the definition `visual.mjs` uses)
  M7 (5317): 2317ms/29f  215ms/25f  224ms/27f  214ms/26f  219ms/26f  1201ms/27f   min 214 median 224 max 2317
  M8 (5314): 1199ms/29f  1013ms/30f 1016ms/30f  228ms/30f  216ms/30f  225ms/30f    min 216 median 1013 max 1199

  Reading: the distribution is bimodal on BOTH milestones. A fast mode of 214-230 ms and a slow mode of
  roughly 1.0-2.3 s that appears without warning on either build. The fast floors are indistinguishable
  (214 vs 216 ms), so no boot regression is demonstrated; the slow mode is a property of this
  workstation's loopback/asset-fetch behaviour, not of the milestone, and its biggest sample came from
  M7 (2,317 ms). Median alone is the wrong statistic for a bimodal sample and is reported only because
  it is the arithmetic; the honest claim is "the same floor, the same two modes, six samples each".
  The single-sample pair that started this (M7 1,557 vs M8 2,183) is now retracted as a comparison and
  kept only as the historical numbers they are.

FRAMES RENDERED IN A FIXED 2 SECONDS (same samples, `f` above)
  M7: 25, 26, 26, 27, 27, 29      M8: 29, 30, 30, 30, 30, 30
  M8 draws at least as many frames as M7 on every sample. Part of that is pixel count: the M8 room
  viewport measures 912x566 in the drawing buffer where M7 measured 912x608 — 6.9% fewer pixels —
  because the identity header and the new in-HTML content take vertical space above the stage at this
  viewport. This is a headless SwiftShader figure and says nothing about a real GPU.

WALK DISTANCE (fixed 1/60 s simulation step, so this is a correctness figure rather than a speed one)
  M7 3.35 m per 2 s, M8 3.35 m per 2 s — identical, as designed (the step was made fixed during M7
  precisely so that distance does not depend on frame rate).

LIMITS OF THESE NUMBERS
Headless SwiftShader on one machine, loopback origin, cold HTTP cache per sample (each sample opens a
new browser context). No real GPU, no throttled network, no Lighthouse run, no second browser, no
physical device. The bundle figures are file sizes and Vite's own gzip estimates; the Express static
server used here transfers assets uncompressed, so none of these numbers is a measured network transfer.
